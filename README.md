# BLE 产品产测模拟器上位机

独立 Windows 上位机，用于管理最多六块 ESP32-WROOM-32D BLE DUT 模拟板。
界面采用与 `factory-gui-test` 一致的产测控制台风格，但项目、数据库和运行环境相互独立。

上位机通过 USB 串口配置模拟板；ESP32 固件使用 UART0、115200 baud、
TX=GPIO1、RX=GPIO3。ESP32 与原测试板之间仍使用 BLE 通信。

## 功能

- 内置从已配置上位机导出的 22 个 BLE 产品模板，包含实际产品名称、PID、完整 Model 和默认字段值。
- 支持 ES4、ES5、S5、E5、H3、E7D（T2DSB 协议族）、CE1/C6DB、E6D 数据结构。
- 产品模板支持新增、查询、修改、删除和复制。
- 协议族可新增、复制和编辑；字段名称、顺序、默认值、数据类型及数组数量均可配置。
- 公开协议、PID、Model/BLE 名称、协议字段、半成品/成品就绪时间均可配置。
- 支持正常、超时不回复和错误长度三种模拟模式。
- 最多管理六个串口节点，可给不同节点分配不同产品。
- 节点显示串口与 BLE 状态；左侧摘要显示所选 ESP32 当前确认的产品、PID、BLE 名称和广播状态。
- 支持主动断开 BLE，避免连接期间配置被 `NODE_CONNECTED` 拒绝。
- 默认以 `2100×1400` 窗口尺寸居中显示，最小尺寸为 `1260×900`；运行日志固定显示在右侧节点区。
- UART6 下方集中显示发现的串口数和当前已连接的串口数，运行日志位于统计条下方。
- BLE 断开事件会在节点状态和运行日志中标红。

现有治具仍通过 MiBeacon Service Data 中的 PID 识别产品。Model 作为
BLE Scan Response 中的 Complete Local Name 下发给固件，UTF-8 编码后最多 29 字节；它用于
扫描列表辨识，不替代 PID 的产品身份语义。

模板参数中的“协议”为可选的公开协议名。E5、H3 等协议可能对应多种字段结构；
从其他协议切换进入时，上位机会要求选择具体字段结构，实际下发仍由该结构打包。

“结果通知延时”表示半成品或成品数据达到就绪时间后，固件在发送结果通知前
额外等待的时间；填 `0` 表示就绪后立即通知。

## 新增新品

1. 点击“新增”，在协议族右侧点击“管理…”。
2. 可直接新增协议族，也可复制最接近的内置协议族后修改。
3. 按实际 Payload 顺序配置字段名称、类型、数量和默认值。
4. 当前支持 `u8/s8/u16/s16/u32/s32`，全部按小端序打包；数组默认值使用英文逗号分隔。
5. 保存协议族后回到新增产品窗口，填写名称、Model/BLE 名称和 PID。
6. 保存模板时会自动校验字段范围和 Payload 长度，通过后再下发到 ESP32。

协议族总 Payload 不能超过固件的 64 字节上限。编辑被多个产品引用的协议族会同步
更新这些产品：同名且类型兼容的字段保留原值，新字段使用默认值，不兼容或已删除的
字段不会继续沿用。内置协议族不能删除或改名，如需派生新品请先复制。

## 运行

推荐直接运行 `dist` 目录中的单文件 EXE，无需安装 Python。

需要从源码运行时，已安装 Python 3.9 及以上后执行：

```powershell
python -m pip install -r requirements.txt
python app.py
```

首次运行会从 `products.json` 初始化产品模板，之后数据库保存在：

```text
%LOCALAPPDATA%\Linptech\BleDutSimulator\products.db
```

`products.json` 只在首次建库时导入；已有数据库及用户已经调整的模板不会被自动覆盖。

## 使用顺序

1. 将包含可配置 BLE 名称、Scan Response 名称和 `DISCONNECT` 命令的 0.2.1 通用模拟固件刷入 ESP32 模拟板。
2. 在右侧节点选择串口并点击“连接”；此处连接的是电脑与 ESP32 的配置串口。
3. 在左侧选择产品，在中间编辑参数并保存模板。
4. 勾选目标节点。如果节点显示“BLE 已连接”，先点击“断开 BLE”。
5. 等日志出现红色的 `BLE 已断开` 事件，再点击“应用配置”。
6. 只有日志出现 `@SIM ACK ... cmd=CONFIG` 且节点显示“配置生效”，配置才真正写入 ESP32。
7. 点击“开始广播”，再让测试板扫描、连接并执行新一轮测试。

“停止广播”只控制是否允许新的 BLE 连接；“断开 BLE”用于释放已经建立的连接；
节点行内的“断开”只断开电脑串口。三种操作的作用不同。

同一产品可以下发给多块板，也可以依次选择不同模板分配给不同节点。

## 状态说明

- `串口在线`：电脑已经连接 ESP32 配置串口。
- `BLE 已连接`：测试板当前占用该模拟节点，此时旧固件会拒绝修改配置。
- `等待 BLE`：串口在线，当前没有测试板连接。
- `BLE 已断开`：刚收到 BLE 断连事件，节点和日志会标红提醒。
- `等待确认`：上位机已发送配置，正在等待 ESP32 ACK。
- `配置生效`：已收到匹配序号的 `CONFIG ACK`。
- `操作失败`：ESP32 返回错误；日志会显示错误代码和恢复方式。

## 调整页面

- 运行日志固定显示在右侧节点区，不提供收起功能。
- 产品模板列表中产品名称靠左、PID 居中，Model 自动占用剩余宽度。
- 搜索框按实际文本变化刷新，回车或离开搜索框时会清理首尾空白。

- 连续缩放窗口时会显示轻量页面骨架，停止拖动后恢复完整控件。

## 重新打包

执行：

```powershell
.\build_app.ps1
```

脚本优先使用本项目 `.venv` 中的 PyInstaller；若本地尚未建立环境，会使用
`factory-gui-test` 已有的打包环境。最终单文件 EXE 生成在 `dist` 目录。

## 测试

```powershell
python -m unittest discover -s tests -v
```

自动化测试覆盖 22 个 BLE PID、动态协议族、32 位字段、Payload 长度、大小端、
有符号字段、BLE 名称编解码、串口配置命令和 SQLite CRUD/兼容迁移。真实串口、主动 BLE 断开、一拖六、广播
名称和治具判定仍需硬件验证。
